# v0.5 generative reconstruction plan

## Objective

Version v0.5 investigates whether the currently audited New Jerusalem geometry
can be generated end-to-end from the formal construction grammar without
source-plate calibration coordinates entering the generative path.

The principal question is:

> Which parts of the current reconstruction are determined by the construction
> grammar, and which still require a project-level choice or unresolved
> historical correspondence?

## Baseline

The immutable baseline is the signed v0.4.0 checkpoint.

v0.5 development begins from:

`2528094e72aad966bf0e46db146f6cacf7cbc963`

The v0.4 frozen predictor used for source validation remains:

the frozen v0.4 predictor.

## Generative input boundary

The complete v0.5 normalized reconstruction should accept only:

`unit`

as a free geometric scale input.

The generative path must not consume:

- source-image pixel coordinates;
- digitised Figure 12 landmarks;
- digitised Figure 14 landmarks;
- affine or projective registration matrices;
- source-derived fitted wall lines;
- source-derived star endpoint coordinates;
- source-calibrated phase or rotation adjustments;
- any post-hoc parameter selected to improve plate agreement.

## Phase 5A — canonical composite geometry

Construct a single in-memory object representing the complete currently
audited NJG_MICHELL geometry.

At minimum it should expose:

- core Earth circle;
- Earth square;
- radius-7 construction circle;
- twelve Moon circles;
- four-by-three Moon grouping;
- preferred polar-pivot wall;
- Method-1 sevenfold construction;
- reciprocal fourteenfold construction;
- four-triangle 28-point construction;
- role-labelled 28-point scaffold;
- scaffold-derived Figure 14 candidate.

No source plate is used as a generative input.

## Phase 5B — deterministic renderer

Generate one transparent-background SVG directly from the composite geometry.

The renderer must not contain independent hand-positioned geometry.

Every rendered geometric object must originate from the same computational
objects used by the test suite.

## Phase 5C — provenance manifest

Every exported geometric element should be associated where practical with:

- stable object identifier;
- geometric type;
- construction-grammar node;
- generating operation;
- evidential status;
- source claim identifiers where applicable;
- project-reconstruction status where applicable.

The provenance manifest must distinguish computational dependency from
historical evidence.

## Phase 5D — machine-readable geometry export

Export the complete normalized reconstruction in deterministic
machine-readable form.

The export should preserve sufficient information to reproduce:

- points;
- circles;
- lines;
- wall vertices;
- wall sides;
- scaffold points;
- star vertices and traversal;
- provenance assignments.

## Phase 5E — generative closure tests

Test at minimum:

1. unit scaling changes lengths linearly;
2. unit scaling changes areas quadratically;
3. normalized angles are invariant;
4. combinatorial topology is invariant;
5. Moon grouping is invariant;
6. scaffold role assignments are invariant;
7. the composite renderer imports no plate-calibration geometry;
8. the machine-readable exporter imports no plate-calibration geometry;
9. deterministic repeated runs are byte-identical where serialization permits.

## Phase 5F — sevenfold phase-selection audit

The v0.4 composite contains a particular seven-point subset of the 28-point
scaffold for the Figure 14 candidate.

v0.5 must determine whether the construction grammar itself uniquely selects
that seven-point phase.

The audit must enumerate the symmetry-related seven-point phase classes of the
28-point scaffold before consulting Figure 14 positional residuals.

Possible outcomes include:

- the construction independently privileges one phase;
- several phases are geometrically equivalent;
- an additional historical rule is required;
- the printed Figure 14 selects among otherwise equivalent project candidates.

A source-plate preference must not be fed back into the generative grammar.

## Interpretation boundary

v0.5 is a construction-sufficiency audit.

A deterministic software dependency does not establish that Michell used the
same historical construction order.

Project reconstructions remain labelled as project reconstructions.

Candidate historical correspondences remain candidates unless independently
supported by source evidence.
