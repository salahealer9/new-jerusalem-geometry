## Purpose

Phase 6B implements deterministic unit arithmetic only.

It does not evaluate whether a historical geometric target agrees with the
frozen `v0.5.0` geometry.

The output of this phase is a formal conversion system and a deterministic
machine-readable unit manifest.

## Canonical linear base

For v0.6 dimensional arithmetic, the canonical linear base is the modern /
current foot.

The registry label `foot` is treated as the same base-length unit as
`current_foot` unless a record explicitly states a different historical foot.

This is an implementation normalization, not a claim that all historical
units called "foot" were physically identical.

The standard exact identity

```text
12 inches = 1 current foot
```

may be used solely for ordinary inch/foot arithmetic.

It is not a Michell-specific metrological claim.

## Registered linear definitions

### UNIT-001 — Megalithic Yard

The registered Michell/Thom convention is:

```text
1 megalithic yard = 2.72 current feet
                  = 68/25 current feet
```

The decimal `2.72` is represented exactly as the rational `68/25` for
reproducible source-convention arithmetic.

This does not assert that a historical physical Megalithic Yard is known to
infinite precision.

### UNIT-002 — Sumerian foot

The registered Michell/Berriman convention is:

```text
1 Sumerian foot = 13.2 inches
                = 1.1 current feet
                = 11/10 current feet
```

The two source expressions must agree exactly under the standard
12-inches-per-foot identity.

### UNIT-003 — New Jerusalem stadion / furlong

The registered relation is:

```text
1 New Jerusalem stadion
    = 600 Sumerian feet
    = 660 current feet
    = 1 furlong
```

Because UNIT-002 fixes the Sumerian foot at `11/10` current foot,

```text
600 × 11/10 = 660
```

must close exactly.

### UNIT-004 — New Jerusalem cubit

The registered New Jerusalem convention is:

```text
1 New Jerusalem cubit = 1.728 current feet
                       = 216/125 current feet
```

The finite decimal is represented exactly as the rational `216/125` inside
the source-defined convention.

### SOMM-006 — old-English/current-foot relation

Michell reports that the old English foot "relates 12:11 to the current foot."

For Phase 6B this is frozen as a ratio of unit lengths:

```text
old-English foot : current foot = 12 : 11
```

Therefore:

```text
1 old-English foot = 12/11 current foot
```

and a physical length expressed as `L` current feet is expressed as

```text
L × 11/12
```

old-English feet.

This direction is frozen before the Phase 6C wall-perimeter calculation.

It may not be reversed later because one direction gives a numerically closer
historical result.

## SCALE-001 — New Jerusalem model scale

The registered relation

```text
1 model foot : 1 source mile
```

is a geometric scale correspondence, not a physical unit identity.

Phase 6B must therefore NOT insert `mile` into the ordinary foot-based unit
conversion graph by treating:

```text
1 foot = 1 mile
```

as a physical conversion.

Instead, the implementation must expose the New Jerusalem scale as a separate
mapping:

```text
numeric source miles -> equal numeric model feet
numeric model feet   -> equal numeric source miles
```

This preserves the meaning of the source's 1-foot:1-mile model statement.

## Pi conventions

Two distinct circumference conventions must be available.

### Michell conventional pi

```text
pi_M = 22/7
```

This is represented exactly as a rational number.

A result exact under this convention is labelled conventional exactness, not
Euclidean exactness.

### Euclidean pi

Euclidean calculations use the language/runtime mathematical value of `pi`.

The implementation must never silently substitute `22/7` for Euclidean pi or
vice versa.

## Area conversion

Area conversion is generated only by squaring an already registered linear
conversion factor.

For example, if:

```text
1 U = q current feet
```

then:

```text
1 square U = q^2 square current feet
```

No separate fitted area-conversion parameter is permitted.

## Exact arithmetic

Registered finite decimals and integer ratios are represented internally with
exact rational arithmetic wherever possible.

The Phase 6B implementation must therefore be able to recover exactly:

```text
2.72 = 68/25
1.1 = 11/10
1.728 = 216/125
13.2 inches = 11/10 current foot
600 Sumerian feet = 660 current feet
old-English/current-foot unit-length ratio = 12/11
```

Floating-point conversion may be exposed for presentation only after the
exact rational result exists.

## Deterministic manifest

Phase 6B will generate a canonical machine-readable manifest containing:

- canonical unit names;
- exact rational conversion factors;
- decimal display values;
- source record IDs;
- provenance class;
- separate New Jerusalem model-scale relation;
- separate `22/7` and Euclidean-pi conventions.

The manifest must contain no machine-specific absolute paths and no geometric
target values.
