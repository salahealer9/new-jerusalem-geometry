# v0.5 NJG_MICHELL generative closure and invariance protocol

## Status

This document preregisters Phase 5E of the v0.5 full generative
New Jerusalem reconstruction.

Phases 5A-5D established:

```text
MichellComposite
      |
      +-- deterministic SVG
      +-- deterministic provenance JSON
      +-- deterministic numerical geometry JSON
````

Phase 5E does not introduce a new geometric reconstruction.

It tests whether the existing construction is generatively closed and whether
its outputs transform correctly under the only exposed geometric degree of
freedom: uniform scale.

## Central question

Can the complete audited `NJG_MICHELL` construction be generated at arbitrary
positive scale while preserving all dimensionless geometry, topology,
semantic roles, provenance structure, and cross-representation identity?

## Null failure modes

Phase 5E is designed to detect failures including:

```text
unit-one constants hidden inside downstream construction;
incorrect linear scaling of coordinates or lengths;
incorrect quadratic scaling of areas;
scale-dependent angular quantities;
scale-dependent topology;
scale-dependent Moon grouping;
scale-dependent scaffold roles;
scale-dependent Figure 14 scaffold selection;
scale-dependent object IDs;
scale-dependent provenance structure;
geometry/provenance identity divergence;
SVG/provenance linkage divergence;
nondeterministic repeated generation;
downstream reconstruction of geometry instead of reuse of MichellComposite.
```

## Tested scales

The registered scale set is:

```text
0.25
0.73
1.00
2.75
8.00
```

All are positive.

The values include:

```text
a sub-unit binary scale;
a non-round sub-unit scale;
the canonical unit-one model;
a non-round super-unit scale;
a large integer scale.
```

The scale set is fixed before evaluating Phase 5E results.

No scale is to be removed because it produces an inconvenient result.

## Reference construction

The canonical reference is:

```text
build_michell_composite(unit=1.0)
```

For each registered scale `s`, construct:

```text
build_michell_composite(unit=s)
```

The scaled construction is compared directly with the unit-one construction.

No source-plate calibration geometry participates in the comparison.

## Required scale laws

### Linear quantities

Every geometric coordinate and physical length must scale as:

```text
Q(s) = s Q(1)
```

This includes, where applicable:

```text
Earth radius;
Earth-square side;
construction-circle radius;
Moon centres;
Moon radius;
wall-line offsets;
wall tangency points;
wall vertices;
wall side lengths;
wall perimeter;
wall mean side length;
sevenfold radius;
sevenfold Cartesian points;
fourteenfold Cartesian points;
scaffold radius;
scaffold Cartesian points;
heptagram Cartesian vertices;
heptagram edge lengths.
```

### Quadratic quantities

Every Euclidean area must scale as:

```text
A(s) = s^2 A(1)
```

This includes at minimum:

```text
polar-pivot wall area.
```

### Dimensionless quantities

Dimensionless and angular quantities must remain invariant.

These include:

```text
wall-line unit normals;
sevenfold step angle;
sevenfold angles;
fourteenfold angles;
fourteenfold angular gaps;
four-triangle angular marks;
four-triangle/scaffold angular mismatch;
scaffold beta;
scaffold heptagonal step;
scaffold point angles.
```

## Object-identity invariance

Every registered scale must generate the same ordered 132-object namespace.

The expected ordered identity is:

```text
(object_id, geometry_type)
```

from the unit-one geometry export.

For every scale:

```text
geometry object identity
    ==
unit-one geometry object identity
```

and:

```text
provenance object identity
    ==
unit-one provenance object identity
```

and:

```text
geometry object identity
    ==
provenance object identity
```

The count must remain:

```text
132
```

## Provenance invariance

Scale must not alter historical or construction provenance.

Across all registered scales, the following must remain byte/logically
identical after excluding the explicit top-level `unit` value:

```text
source hashes;
object records;
grammar nodes;
construction dependencies;
claims;
grammar-node memberships;
source-object relationships;
rendered-SVG identities.
```

In particular, scale must not change:

```text
node_type
relation_type
evidence_status
source_status
claim_ids
```

No evidential classification is allowed to depend on geometric scale.

## Geometry/provenance separation

The geometry representation must continue to contain no evidence vocabulary.

The provenance representation must continue to contain no source-derived
geometric coordinates.

Phase 5E must not merge the two representations merely to simplify testing.

## SVG structural invariance

For every registered scale, the SVG must preserve the same semantic structure.

Required counts are:

```text
12 Moon circles
28 scaffold markers
7 heptagram vertices
7 heptagram edges
59 data-provenance-id links
```

The set of SVG provenance identifiers must remain exactly invariant.

The SVG byte stream is not expected to be invariant across different scales,
because coordinates and the geometric viewBox change.

## Same-input determinism

For every registered scale, repeated construction and export must be
deterministic.

For identical input scale `s`:

```text
geometry JSON run 1 == geometry JSON run 2
provenance JSON run 1 == provenance JSON run 2
SVG run 1 == SVG run 2
```

Byte equality is required.

This is distinct from cross-scale invariance.

## Generative closure

The complete downstream path must succeed from:

```text
unit
  |
  v
build_michell_composite
  |
  +-- geometry export
  +-- provenance export
  +-- SVG renderer
```

without introducing:

```text
source pixels;
source landmarks;
registration matrices;
Figure 12 fitted geometry;
Figure 14 fitted coordinates;
calibration-derived coordinates;
post-hoc scale-specific adjustments.
```

The test suite should retain AST/import-boundary checks established in earlier
phases.

## No downstream rebuild

The Phase 5B, 5C and 5D downstream modules must continue to consume a supplied
`MichellComposite`.

They must not call `build_michell_composite()` internally.

Application-level generator scripts are permitted to construct the composite.

## Numerical comparison policy

For deterministic discrete structures, exact equality is required.

For floating-point scaling tests, use strict numerical comparison appropriate
to double-precision arithmetic.

Registered default tolerance:

```text
relative tolerance = 1e-12
absolute tolerance = 1e-12
```

When testing:

```text
scaled_value ~= reference_value * scale
```

the tolerance applies to floating-point arithmetic only.

It must not be loosened in response to a failing category without explicit
documentation and justification.
