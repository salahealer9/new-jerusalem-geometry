# v0.6 Phase 6C — frozen dimensional prediction protocol

## Status

Preregistered prediction protocol.

The predictor is the signed `v0.5.0` `NJG_MICHELL` geometry combined with the
formal Phase 6B source-defined unit system.

Phase 6C is deliberately blind to historical wall and decagon target values.

## Central question

What dimensional quantities follow from the frozen `v0.5.0` geometry when
expressed through the frozen Phase 6B unit system, without fitting or
comparison to historical dimensional targets?

## Frozen inputs

### Geometry

The geometric predictor is the signed `v0.5.0` checkpoint:


Phase 6C may use the canonical `NJG_MICHELL` composite and deterministic
geometry exported by that checkpoint.

No source-plate coordinates, calibration residuals, registration transforms,

## Scale derivation

The dimensional scale is not a free parameter.

The frozen core geometry has Earth-square side:

```text
11 normalized units
```

The registered source/model scale gives the corresponding New Jerusalem
Earth-square side as:

```text
7920 model feet
```

Therefore Phase 6C derives:

```text
1 normalized unit = 7920 / 11 model feet
                  = 720 model feet
```

The value `720 model feet per normalized unit` is therefore a deterministic
consequence of the frozen construction input and is not fitted to any wall
quantity.

For area:

```text
1 normalized unit^2 = 720^2 square model feet
                    = 518400 square model feet
```

The implementation must derive these factors rather than introduce a second
independent wall scale.

## Allowed geometric quantities

Phase 6C is registered to emit the following quantities from the frozen
`POLAR_PIVOT_WALL` geometry.

### Linear wall predictions

1. `polar_side_current_foot`
   - one representative side from the four frozen polar sides;
   - all four must agree within numerical tolerance.

2. `oblique_side_current_foot`
   - one representative side from the eight frozen oblique sides;
   - all eight must agree within numerical tolerance.

3. `mean_side_current_foot`
   - arithmetic mean of all twelve frozen wall side lengths.

4. `wall_perimeter_current_foot`
   - sum of all twelve frozen wall side lengths.

5. `wall_perimeter_megalithic_yard`
   - `wall_perimeter_current_foot` converted through the frozen
     Phase 6B Megalithic-Yard definition.

6. `wall_perimeter_old_english_foot`
   - `wall_perimeter_current_foot` converted through the frozen
     Phase 6B old-English-foot definition.

### Area prediction

7. `wall_area_square_foot`
   - area of the frozen wall polygon after applying the derived
     `720 model feet / normalized unit` scale.

No other wall quantity may be introduced into the canonical Phase 6C manifest
without a new preregistered extension.

## Structural checks

Before dimensional conversion, Phase 6C must verify that the frozen wall has:

```text
12 sides total
4 polar sides
8 oblique sides
12 vertices
```

The polar and oblique classes must be identified from the frozen semantic wall
structure, not by selecting whichever sides happen to be numerically longer
or shorter after dimensional conversion.

## Prediction independence from historical targets

The Phase 6C implementation path must not contain or consume these historical
target values:

```text
3264
3280
3270
36000
120000000
6336
6300
```

These values remain in the frozen Phase 6A historical registry, but they are
not inputs to the predictor.

The Phase 6C prediction module must not import the historical metrology
registry directly.

It may import only:

- the frozen geometry implementation/export;
- the Phase 6B formal unit-system implementation;
- standard-library numerical utilities.

This keeps source-target metadata and geometric prediction code separated.

## No residuals in Phase 6C

Phase 6C must not calculate:

- signed target residual;
- absolute target residual;
- relative target residual;
- percent target residual;
- target rank;
- pass/fail against historical tolerance;
- "prediction success" or "prediction failure".

Those belong downstream after the prediction artifact is frozen.

## Numerical representation

### Geometry

The existing floating-point `v0.5.0` geometry values are used without
refitting.

### Scale

The linear scale factor `720` is represented exactly.

### Unit conversion

Where Phase 6B provides exact rational conversion, it must remain exact until
combined with the floating-point geometric quantity.

### Presentation

Canonical prediction values should retain sufficient precision to reproduce
the current deterministic geometry.

Human-readable rounding must not alter the canonical stored value.

## Canonical output

Phase 6C will generate:

```text
data/metrology/njg_michell_v0_6/frozen_dimensional_predictions.json
```

The manifest must contain:

- schema version;
- phase identifier;
- frozen v0.5 geometry commit;
- frozen Phase 6B manifest hash;
- derived linear scale;
- derived area scale;
- wall structural counts;
- normalized geometric values;
- dimensional predictions;
- unit labels;
- source-unit record IDs used for conversions;
- explicit statement that historical targets were not loaded;
- explicit statement that residuals were not calculated.

It must contain no absolute machine-specific path.

## Determinism

Two consecutive regenerations from the same repository state must produce
byte-identical prediction artifacts and identical SHA-256 hashes.

## Required tests

Phase 6C implementation must test:

1. frozen geometry commit/provenance identifier is recorded;
2. frozen Phase 6B manifest hash is verified;
3. scale derives exactly as `7920 / 11 = 720`;
4. area scale derives as `720^2`;
5. wall contains exactly 12 sides and 12 vertices;
6. semantic side classes contain exactly 4 polar and 8 oblique sides;
7. all four polar side lengths agree within fixed numerical tolerance;
8. all eight oblique side lengths agree within fixed numerical tolerance;
9. mean side is calculated from all twelve sides;
10. perimeter is the sum of all twelve sides;
11. polygon area comes from the frozen wall geometry;
12. Megalithic-Yard perimeter conversion uses Phase 6B;
13. old-English-foot perimeter conversion uses Phase 6B;
14. historical target literals are absent from the Phase 6C module;
15. Phase 6C module does not import/load the Phase 6A historical target
    registry;
16. prediction artifact contains no residual fields;
17. prediction artifact contains no absolute home path;
18. deterministic regeneration is byte-identical.

## Leakage test vocabulary

The canonical prediction artifact must not contain fields whose names include:

```text
target
residual
error_percent
percent_error
historical_match
tolerance_pass
```

A provenance field such as:

```text
historical_targets_loaded = false
```

is allowed because it records the blind-prediction boundary.

## Phase 6C closeout condition

Phase 6C closes only after:

- prediction protocol is frozen;
- implementation tests pass;
- full repository suite passes;
- canonical prediction artifact is deterministic;
- artifact hash is recorded;
- no historical target values or residual computations have entered the
  predictor.

Only after the prediction artifact itself is sealed may Phase 6D inspect
provenance/leakage classification and Phase 6E compare the frozen predictions
against historical targets.

## Version boundary

The package version remains `0.5.0`.

No version bump occurs during Phase 6C.
