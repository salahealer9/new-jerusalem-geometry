# v0.5.0 integration and release-readiness protocol

## Purpose

Phase 5G is the final integration audit for the v0.5 full generative
New Jerusalem reconstruction.

Its purpose is to determine whether the complete v0.5 work can be promoted
from the feature branch to the signed `v0.5.0` repository checkpoint.

No new geometric model selection is permitted during this phase.

## Frozen scientific state

Phase 5G begins after completion of:

```text
Phase 5A
canonical full generative geometry

Phase 5B
deterministic composite SVG renderer

Phase 5C
deterministic provenance manifest

Phase 5D
complete machine-readable geometry export

Phase 5E
generative closure and scale-invariance audit

Phase 5F
sevenfold phase-selection audit
````

The Phase 5F checkpoint entering Phase 5G is:

```text
4e6722e
Resolve sevenfold phase source consistency
```

## Central readiness question

The release-readiness question is:

```text
Can the v0.5 integrated reconstruction be regenerated deterministically,
pass the complete repository test suite, preserve its evidence boundaries,
and expose internally consistent geometry, provenance, SVG, and audit
artifacts without relying on source-calibration geometry in the generative
path?
```

## No model changes

Phase 5G must not:

```text
change the core geometry
change Moon placement
change the polar-pivot wall
change the 28-point scaffold
change the Figure 14 phase
change the {7/2} topology
change any Stage A or Stage B result
refit source calibration
introduce new geometric degrees of freedom
```

Any scientific defect discovered during Phase 5G must be documented and fixed
explicitly before release readiness can be declared.

## Required complete test suite

The complete repository test suite must pass.

The baseline entering Phase 5G is:

```text
320 passed
```

A higher count is acceptable if Phase 5G adds integration tests.

No existing test may be removed merely to obtain a passing release.

source-coordinate, or source-fitting modules.

the generative construction path.
