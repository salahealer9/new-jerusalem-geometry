# v0.9 exact-sevenfold constructibility protocol

## Status

Preregistered project protocol for the `v0.9.0` exact-sevenfold boundary audit.

This protocol is written before any v0.9 native-incidence census or
cubic-capable extension search is executed.

The protocol separates:

```text
A. Euclidean closure
B. native-incidence census
C. minimal cubic-capable extension
```

Only A and B are executable under the first v0.9 analysis phase. C is
explicitly deferred until A and B have been frozen.

## Mathematical target

Let:

```text
theta_7 = 2*pi/7
c_7     = cos(theta_7)
y_7     = 2*cos(theta_7)
```

The exact target polynomial to verify is:

```text
f(y) = y^3 + y^2 - 2*y - 1
```

equivalently:

```text
g(c) = 8*c^3 + 4*c^2 - 4*c - 1.
```

Phase B must verify mechanically that:

```text
f(y_7) = 0
```

and that `f` is irreducible over the rationals.

For this cubic, irreducibility may be certified by the rational-root theorem:
the only possible integer rational roots are `+1` and `-1`, and neither is a
root.

The resulting target degree is therefore:

```text
[Q(y_7) : Q] = 3.
```

## Classical constructibility criterion

The project uses the classical straightedge-and-compass criterion associated
with Wantzel's theorem:

A point produced from rational seed data by a finite chain of ordinary
line/line, line/circle, and circle/circle constructions has coordinates in a
tower of extensions of degree at most two at each step.

Therefore every algebraic coordinate in the Euclidean constructible closure
has degree over `Q` equal to a power of two.

For the present audit, this theorem is treated as an external mathematical
theorem. The repository must verify that the admitted New Jerusalem seeds and
operations lie inside that Euclidean construction class; it must not pretend
to re-prove the full historical theorem from numerical experiments.

Primary historical reference:

```text
L. Wantzel,
"Recherches sur les moyens de reconnaître si un Problème de Géométrie
peut se résoudre avec la règle et le compas",
Journal de Mathématiques Pures et Appliquées,
Série 1, Tome 2 (1837), 366-372.
```

## Question A — Euclidean closure

### A1. Question

Can the exact regular-heptagon angle `2*pi/7` arise from the admitted New
Jerusalem geometry using only ordinary unmarked straightedge-and-compass
operations?

### A2. Primary criterion

Question A is answered at the algebraic-field level, not by a finite brute
force search over diagrams.

The audit must establish both:

```text
1. every admitted NJG-native seed belongs to the Euclidean constructible
   closure of the rational core data;

2. y_7 = 2*cos(2*pi/7) has algebraic degree 3 over Q.
```

If both statements hold, then the exact sevenfold target cannot belong to the
Euclidean closure of the admitted NJG-native geometry.

### A3. Important meaning of "using the diagram's own elements"

Existing constructible irrational quantities are allowed.

Examples include:

```text
sqrt(3)
square-circle intersection coordinates
Method 1 nested square-root quantities
Method 2 sqrt(3)/2 chord geometry
Method 2 cos(alpha_2) = 5/8
constructible tangent points
constructible rotations by 30, 60, 90, or other already generated
Euclidean angles
```

The theorem does not require the starting field to be only rational after
those quantities have been constructed. A finite tower of quadratic
extensions remains inside the classical constructible closure.

## Target-injection exclusions

The kickoff inventory revealed existing exact-heptagon reference objects in
the repository. They are essential for comparison but are inadmissible as
"hidden discoveries".

The following must be excluded from every candidate registry:

```text
ObliqueModel.DIVISION_28
NJG_28 when it is generated from ObliqueModel.DIVISION_28
build_regular_heptagram
free regular seven-vertex fits
exact_heptagon_step_radians
exact_heptagonal_step_radians
any direct 2*pi/7 reference
any object whose defining input already contains pi/7 or 2*pi/7
```

Reason:

```text
ObliqueModel.DIVISION_28
```

is already tested in the frozen repository as having an angle exactly equal
to `pi/7`. It is therefore a target-defined comparator, not an independent
construction of `pi/7`.

Likewise, an exact regular-heptagram helper is a reference geometry. Finding
the target inside one of these objects would be circular and must never count
as a v0.9 result.

Constructible symmetry constants such as `pi/2` and `pi/3` are not excluded
when their geometric provenance is respectively square/cardinal or
equilateral-triangle symmetry. The exclusion concerns direct injection of the
sevenfold target.

## Computational implementation versus Euclidean lineage

Existing project code sometimes computes coordinates using trigonometric
functions as a deterministic implementation shortcut.

A direct call such as:

```text
cos(angle)
sin(angle)
```

does not by itself prove that the angle is a Euclidean construction.

Conversely, use of trigonometric functions in code does not make a
source-described Euclidean construction nonconstructible.

Phase B must therefore classify objects by their construction lineage and
exact algebraic definitions, not by whether Python happens to use `sin`,
`cos`, or `acos`.

## Question B — native-incidence census

### B1. Purpose

Question A addresses the complete Euclidean closure theorem.

Question B asks the narrower descriptive question:

Does any already-existing canonical NJG-native point, line, ray, or registered
native incidence carry the exact sevenfold direction without generating any
new construction step?

### B2. Candidate registry

The finite census may contain only canonical N0 objects, plus N1 objects after
their Euclidean lineage is verified.

Registered candidate feature classes are:

```text
1. radial directions from the construction centre to native points;

2. angular separations between pairs of native radial directions;

3. directions of native straight lines already present in the generative
   construction;

4. already-existing line/circle and circle/circle incidence points explicitly
   present in the frozen generative grammar;

5. source-described Method 1 and Method 2 carrier/intersection directions;

6. existing Moon-centre and square-circle-intersection directions.
```

Question B does not recursively generate new lines, circles, or intersections.
That infinite-closure question is already answered by Question A.

### B3. Semantic deduplication

Symmetry-related duplicates may be grouped only after their exact semantic
provenance has been retained.

Every candidate record must preserve:

```text
candidate_id
source_node
construction_lineage
feature_type
exact_expression_or_symbolic_definition
symmetry_class
target_injected = false
```

### B4. Exact acceptance criterion

No numerical tolerance can establish a successful exact-sevenfold candidate.

A candidate counts as exact only if symbolic algebra proves one of the
registered equivalent identities, for example:

```text
angle = 2*pi/7 modulo the registered orientation symmetry

or

2*cos(angle)
```

is proven to be the intended real root of:

```text
y^3 + y^2 - 2*y - 1 = 0
```

with the required angular/root interval fixing the correct root.

Floating-point residuals may be reported only as descriptive diagnostics after
the exact symbolic classification.

### B5. Near matches

Near matches are not discoveries.

The census may report the closest native directions descriptively, but:

```text
no tolerance
no ranking cutoff
no percentile
no best-of-N selection
no post-hoc candidate promotion
```

may turn a near match into an exact construction.

### B6. Conflict rule

If a purported exact candidate is found in N0 or verified N1, execution stops
before interpretation.

The candidate must first be audited for:

```text
direct target injection
use of DIVISION_28
use of a regular-heptagon reference helper
use of source-calibrated measured coordinates
unregistered non-Euclidean operations
symbolic simplification error
```

Only after that provenance audit may it be classified.

## Question C — minimal cubic-capable extension

Question C is not executed in the first A/B analysis phase.

It becomes eligible only after A and B are frozen.

The later protocol may investigate a single additional operation capable of
crossing the cubic algebraic boundary, such as a marked-ruler/neusis or an
equivalent conic/origami operation.

The extension must be separately preregistered.

It must specify:

```text
the exact allowed operation
the mark or incidence constraints
which frozen NJG-native points/lines/circles may anchor it
the number of permitted non-Euclidean operations
the exact success polynomial
the root-selection rule
the candidate enumeration rule
the stopping rule
```

No candidate neusis, marked-ruler, origami, or conic construction may be
searched during Phase B.

Reference for the later cubic-capable extension class:

```text
Roger C. Alperin,
"A Mathematical Theory of Origami Constructions and Numbers",
New York Journal of Mathematics 6 (2000), 119-133.
```

The later extension audit must not imply that Michell or Sommerville used,
knew, or intended such an operation unless independent historical evidence is
found.

## Stopping rule

The first v0.9 execution phase terminates when:

```text
1. the target cubic and its degree are verified;

2. the admitted N0 Euclidean construction lineage is audited;

3. target-injected reference objects are mechanically excluded;

4. the registered finite native-incidence census is complete;

5. every exact-candidate claim has passed the conflict/provenance rule;

6. deterministic JSON and Markdown artifacts are generated;

7. the complete repository test suite passes.
```

The intended terminal audit status is:

```text
EXACT_SEVENFOLD_BOUNDARY_AUDIT_COMPLETE
```

This status means the preregistered A/B audit finished. It does not depend on a
desired discovery outcome.

## Interpretation boundary

A Euclidean no-go result would establish a mathematical constructibility
boundary for the admitted New Jerusalem generative geometry.

It would not establish that Michell or Sommerville attempted every possible
construction.

A native-incidence null result would establish only that no exact target was
found in the finite preregistered registry of already-existing canonical
features.

A later one-operation cubic construction, if found, would establish that the
New Jerusalem geometry can serve as an anchoring framework for that added
operation.

It would not by itself establish historical knowledge, intention, ancient
provenance, physical significance, or metaphysical significance.
