# v0.6 Phase 6E — historical residual and sensitivity protocol

## Status

Preregistered residual-comparison protocol.

Phase 6E is downstream of:

- the frozen Phase 6A historical registry;
- the frozen Phase 6B unit system;
- the frozen Phase 6C dimensional predictions;
- the frozen Phase 6D prediction-status / leakage audit.

This is the first v0.6 phase permitted to combine historical numeric values
with frozen prediction values.

## Central question

How far do the frozen Phase 6C dimensional values lie from the registered
historical values, under the evidential interpretation already frozen by
Phase 6D?

The numerical result cannot change the evidential status of any record.

## Historical target source

For every comparison row the canonical historical target is the frozen
registry's:

```text
source_value
source_unit
```

Phase 6E must not:

- replace the registered primary value with a secondary expression;
- choose whichever equivalent unit gives a smaller residual;
- choose a different historical edition or source number;
- average multiple historical numbers;
- tune the target value.

Where the registry provides:

```text
secondary_value
secondary_unit
```

the secondary expression is used only for a source-consistency / unit
invariance check.

It does not create another evidential target.

## Prediction source

Every predicted value comes directly from the frozen Phase 6C artifact.

Phase 6E must not call the geometric builder to regenerate or alter the
prediction.

This phase compares frozen artifacts to frozen artifacts.

## Unit matching

The primary residual is always calculated in the registered `source_unit`.

The implementation may use the frozen Phase 6B exact unit definitions to
convert the relevant Phase 6C prediction into that unit.

No conversion constant may be introduced locally in the Phase 6E comparison
module if the Phase 6B unit system already defines it.

Linear and area quantities must remain dimensionally distinct.

## Residual sign convention

For historical target `T` and frozen prediction `P`, in the same unit:

```text
signed_residual = P - T
```

Therefore:

```text
positive residual -> frozen prediction is larger than source value
negative residual -> frozen prediction is smaller than source value
```

The remaining canonical metrics are:

```text
absolute_residual = abs(P - T)

relative_residual = (P - T) / T

percent_residual = 100 * (P - T) / T

absolute_percent_residual = abs(percent_residual)
```

All seven registered target values must be non-zero.

No other goodness-of-fit statistic is preregistered.

## No aggregate score

Phase 6E must not calculate:

- a mean percent residual across records;
- an RMS across heterogeneous historical quantities;
- a chi-square;
- a combined p-value;
- a likelihood;
- a Bayes factor;
- a success count;
- an overall pass fraction;
- an optimization score.

The seven rows are historically and evidentially heterogeneous.

Their residuals are reported individually.

## No ranking

Rows must remain in Phase 6D / registry order.

They must not be sorted by:

- smallest residual;
- largest residual;
- percent agreement;
- apparent quality of match.

This prevents the report presentation from becoming a post-hoc selection
device.

## Sensitivity analysis

Phase 6E uses only preregistered, non-fitting sensitivity checks.

### 1. Unit-reexpression invariance

For every linear comparison for which Phase 6B provides an exact conversion,
re-express both prediction and historical target in current feet.

The relative and percent residuals must remain invariant up to fixed numerical
roundoff.

For the old-English-foot comparison, this explicitly checks that converting
both sides with the frozen `12:11` relation does not change the relative
difference.

### 2. Equivalent historical-expression consistency

Where a registry row contains both a primary and a secondary historical
expression, Phase 6E must convert both expressions through Phase 6B and report
whether they are exactly equivalent under the registered unit convention.

The canonical example is the Figure 12 mean-side statement expressed in
current feet and Megalithic Yards.

This is a source-consistency check, not a second prediction test.

### 3. Area-unit consistency

Area conversion must square the registered linear conversion.

No independent area conversion factor may be fitted or introduced.

### 4. Duplicate-evidence sensitivity

`WALL12-003` and `SOMM-003` contain the same approximate wall-area magnitude
in distinct source / attribution contexts.

Both rows remain in the report because both are registered historical records.

They must also be marked:

```text
duplicate_numeric_evidence_group = wall_area_120m
independent_numeric_evidence = false
```

They may not be counted as two independent confirmations.

### 5. Approximation-language boundary

Words such as:

```text
close
approximately
virtually
```

do not define a numerical uncertainty distribution.

Phase 6E therefore assigns:

```text
inferred_source_uncertainty = none
posthoc_tolerance = none
```

No rounding interval or error bar is inferred unless one was already
numerically registered before Phase 6E.

`SOMM-004` is still context-only and is not applied as a threshold.

## Numerical precision

Registry decimal strings should be parsed without unnecessary precision loss.

Where possible, exact decimal source targets should be represented using
`Decimal` or `Fraction` before combination with the floating-point Phase 6C
prediction.

The canonical JSON stores enough precision to reproduce the residual from the
frozen inputs.

Human-readable Markdown may round for presentation but must retain the
canonical machine-readable value alongside or behind the display.

## Required Phase 6E tests

The implementation must verify:

1. Phase 6A registry hash is unchanged;
2. Phase 6B unit-manifest hash is unchanged;
3. Phase 6C prediction hash is unchanged;
4. Phase 6D audit hash is unchanged;
5. exactly seven numerical-comparison rows are emitted;
6. comparison record order exactly follows the frozen Phase 6D order;
7. six rows are `retrospective_residual`;
8. one row, `WALL12-002`, is `descriptive_residual`;
9. no row is labelled an independent forward prediction;
10. the source target comes from `source_value` / `source_unit`;
11. the Phase 6C quantity name is inherited unchanged from Phase 6D;
12. the prediction value is loaded from Phase 6C rather than recomputed from
    geometry;
13. signed residual equals `prediction - source`;
14. absolute residual equals the absolute signed residual;
15. relative residual equals signed residual divided by source;
16. percent residual equals 100 times relative residual;
17. absolute-percent residual is non-negative and equals the absolute percent
    residual;
18. all seven source values are non-zero;
19. linear unit re-expression preserves relative residual within a fixed
    `1e-12` absolute tolerance;
20. equivalent secondary source expressions, where present, are checked but do
    not create extra comparison rows;
21. area conversion uses the square of the frozen linear conversion;
22. `WALL12-003` and `SOMM-003` share the duplicate area evidence group and
    are not marked independent;
23. `SOMM-004` produces no residual and no pass/fail result;
24. all four decagon rows produce no residual;
25. no aggregate goodness-of-fit score is produced;
26. no comparison ranking is produced;
27. no post-hoc tolerance or inferred source uncertainty is introduced;
28. canonical JSON / CSV / Markdown regeneration is deterministic;
29. generated artifacts contain no absolute machine-specific home path;
30. package version remains `0.5.0`.
