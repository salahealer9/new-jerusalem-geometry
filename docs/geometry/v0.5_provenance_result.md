# v0.5 NJG_MICHELL provenance result

## Status

Phase 5C implements a deterministic machine-readable provenance system for the
complete `NJG_MICHELL` generative composite.

The provenance layer describes an already constructed `MichellComposite`.

It does not reconstruct geometry and does not introduce an independent
historical-evidence vocabulary.

## Architecture

The completed provenance architecture is:

```text
MichellComposite
      |
      +-- geometric object inventory
      |
      +-- construction-grammar references
      |
      +-- ancestor-closed grammar snapshot
      |
      +-- geometric-claim references
      |
      +-- authoritative-source hashes
      |
      v
MichellCompositeProvenance
      |
      +-- deterministic JSON
      |
      +-- SVG provenance linkage
````

The authoritative evidence sources remain:

```text
docs/specification/construction_nodes.csv
docs/specification/construction_dependencies.csv
docs/sources/geometric_claim_matrix.csv
```

The JSON manifest is a deterministic audit representation of those sources,
not a replacement for them.

## Evidence separation

Phase 5C preserves five different concepts:

```text
geometry_type
node_type
relation_type
evidence_status
source_status
```

They are not collapsed into a generic provenance label.

In particular, individual geometric objects do not receive an independent
`evidence_status`.

Evidence status remains a property of construction dependencies.

## Grammar closure

The JSON contains an ancestor-closed snapshot of the grammar required to
interpret the object inventory.

This closure is narrower than an earlier diagnostic that collected claims from
any dependency touching a broad set of generative nodes.

The two claim counts therefore need not be identical.

For example, `GAP_ARITHMETIC` is downstream of `SCAFFOLD_28`; it is not an
ancestor required to generate a scaffold provenance object and is therefore
not automatically included merely because the scaffold exists.

This is intentional.

## Source binding

The manifest records SHA-256 hashes of the authoritative:

```text

construction_dependencies.csv
geometric_claim_matrix.csv
```

Consequently a provenance JSON can be tied to the exact grammar and claim
catalogue from which its snapshot was produced.

## Determinism

inputs is byte-identical.

`data-provenance-id` metadata was subsequently added:

```text

```

This confirms that rendering linkage metadata does not feed back into the
provenance model.
