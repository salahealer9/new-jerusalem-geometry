# v0.5 complete generative SVG renderer

## Status

Phase 5B implements the first complete deterministic SVG rendering of the
integrated `NJG_MICHELL` generative geometry.

The renderer is a pure downstream view of an already constructed
`MichellComposite`.

It does not reconstruct geometry independently.

## Architecture

The rendering path is:

```text
build_michell_composite(unit)
          |
          v
    MichellComposite
          |
          v
michell_composite_to_svg()
````

The renderer itself does not accept a geometric `unit` parameter and does not
call `build_michell_composite()`.

The command-line generation script is the application boundary that constructs
the composite and passes it to the renderer.

## Rendered layers

The complete SVG contains:

```text

EARTH_SQUARE

MOON_GROUPS_4X3

The visible geometry contains:

7 heptagram edges
12-sided polar-pivot wall
1 Earth circle
1 Earth square
1 construction circle
```

## Geometric provenance boundary

Every plotted coordinate is read from the supplied `MichellComposite`.

The renderer does not import or invoke:

* Figure 12 calibration geometry;
* Figure 14 calibration geometry;
* digitisation modules;
* registration modules;
* source-derived wall geometry;
* Figure 14 aligned anchor builders;
* alternative Moon-placement builders;
* alternative wall builders;
* independent scaffold builders.

This prevents the renderer from becoming a second geometric construction path.

## SVG structure

The principal SVG groups carry stable semantic identifiers:

```text
njg-michell-composite
wall
construction-circle-layer
earth-square-layer
earth-circle-layer
moon-system
scaffold
heptagram
```

Construction layers also carry `data-grammar-node` attributes.

The heptagram layer records:

```text
data-grammar-node="FIG14_HEPTAGRAM_7_2"
data-vertex-source="FIG14_SCAFFOLD_VERTICES"
```

These annotations establish the initial bridge to the more complete provenance
manifest planned for Phase 5C.

## Construction versus final geometry

The 28 scaffold points are intentionally rendered more subtly than the primary
diagram geometry.

This visually distinguishes construction scaffolding from the principal
geometric elements without removing the scaffold from the reproducible
construction view.

## Coordinate convention

The SVG preserves the mathematical coordinates stored by the computational
model.

The mathematical positive-y direction is converted to SVG screen orientation
only through a rendering-time vertical reflection.

No geometric coordinate is altered for visual alignment.

## Transparency

The SVG contains no rendered background rectangle or CSS background property.

The intended background is transparent.

## Determinism

Repeated rendering of an identical `MichellComposite` is byte-identical.

The canonical `unit = 1.0` SVG generated during Phase 5B has SHA-256:

```text
a625f52c4e0f2a19c17aabe345660a9ea33dba82d65b5e335cc34db3915f6388
```

The hash records the Phase 5B renderer state and may change in later v0.5
phases if provenance metadata is intentionally added to the SVG.

## Visual inspection

The canonical generated plate was visually inspected after structural testing.

The inspection found:

* no clipping of the outer wall;
* complete twelve-Moon rendering;
* clear Earth-circle and Earth-square geometry;
* visible but subordinate 28-point scaffold markers;
* complete seven-edge `{7/2}` heptagram;
* coherent layer alignment;
* sufficient distinction between construction and principal geometry.

No geometric or rendering defect requiring correction was identified.

## Reproduction

Generate the SVG with:

```bash
python scripts/generate_michell_composite.py
```

Default output:

```text
figures/generated/njg_michell_composite.svg
```

The renderer can also be called directly on an existing composite:

```python
from new_jerusalem_geometry import (
    build_michell_composite,
    michell_composite_to_svg,
)

composite = build_michell_composite()

svg = michell_composite_to_svg(
    composite
)
```
